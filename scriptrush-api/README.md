# ScriptRush API

This directory preserves the source serving the existing `scriptrush-api.vercel.app` alias, recovered from deployment `dpl_EGabBKrzr3ugEQTba9mWKiMFv8oh`. Research, diagnostic and memory behavior remain intact.

Generation first extracts all requested features and UI requirements, then produces one complete Lua/Luau block and reviews actual control-to-behavior coverage. A failed feature/UI check receives one targeted repair and another review. Missing, incomplete or unreviewed output returns a structured 502; it never becomes a generic fallback success. Full hubs have a larger output budget, without smaller truncated retries. Explicit user layout, colors, labels and language take priority over defaults.

The full accepted prompt, context and correction input are preserved. Missing game-specific evidence produces clearly unavailable controls and a feature checklist; standard client/UI functions do not require a game scan. The model and source-evidence checks are static, not an execution guarantee. With both server-side keys configured, the backend prioritizes APInex's `free/gpt-6-luna` and automatically tries OpenRouter's `apodex/apodex-1.1-mini:free` when APInex reaches a quota/capacity limit or has a classified transient failure. OpenRouter is restricted to the verified `novita` provider, required response parameters, and zero prompt/completion token prices; paid models and provider fallbacks are disabled. Each credential is bound to its own fixed provider origin, and redirects are rejected. Credentials stay server-side in the existing Vercel API project. APInex responses are consumed as SSE under the same bounded deadline; missing completion metadata, malformed events, provider errors and cut streams cannot be accepted as complete output.

The transport now supports a bounded chain of explicitly configured providers, preserving the current stage, full input, output budget, cancellation and deadline. Quota/capacity and classified transient failures allow a different provider; invalid credentials, malformed output and incomplete completions do not trigger hidden extra requests. Each provider is attempted once per chain pass. With only one configured provider, an explicit short `Retry-After` on a non-daily 429 may still resume that stage once within the deadline, preserving existing minute-limit recovery. A bounded per-process cooldown avoids immediately probing an exhausted route again; it is not a global account quota ledger. Usage reports actual transport attempts, including zero when a cooldown rejects without a request, rather than counting only logical stages. Character counts remain diagnostic estimates, not provider tokens or billing measurements.

The authorized chain is **APInex, then OpenRouter** when both keys are configured. During a cooldown the available route is used first; APInex regains priority when its cooldown expires. If both routes are exhausted, generation returns an honest error without an infinite retry loop. The existing OpenRouter key is already stored as a Sensitive Vercel secret; no new account, key, or paid purchase is required for this configuration. This describes routing behavior, not a claim that a deployment or live model request has passed verification. Kaggle remains inactive because its standard terms exclude serving third-party visitors, and NVIDIA's trial endpoint was excluded because it restricts production use. See [provider research and routing details](docs/providers.md).

The writer receives standard Roblox UI API patterns while the user's requested design remains authoritative. Source proof follows real event handlers and shared factories, supports Luau parameter types, and rejects observed invalid UI casing/events, unretained global input listeners and immediate calls before local function declarations. These guards are deliberately conservative and do not replace in-game testing. A successful provider HTTP response alone is not a passing generation: the complete code and coverage review must also pass. See the frontend delivery record for the actual release and acceptance status.

`GET /api/health` reports service configuration, not provider availability. `GET /api/research-game` identifies a game. `POST /api/guest-chat` accepts build/fix requests. Static review is a rejection check, not proof that a generated script runs correctly inside Roblox.
